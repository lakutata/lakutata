# 国际化（i18n）

`lakutata/com/i18n`（子包 `@lakutata/i18n`）按**键名**管理各语言的消息：代码里写键名，每种语言在自己的文件里给出这个键的句子。消息使用 [ICU MessageFormat](https://unicode-org.github.io/icu/userguide/format_parse/messages/) 的语法，数字、货币、日期和复数由 Node.js 内置的 `Intl` 按语言格式化，不依赖第三方库。

## 翻译文件

一种语言一个 JSON 文件，文件名是语言标签（BCP 47：`en`、`zh-CN`、`zh-Hant-TW`）：

```
locales/
  en.json
  zh-CN.json
```

```json
{
  "order": {
    "count": "{count, plural, =0 {还没有订单} other {共 # 个订单}}",
    "created": "已为 {customer} 创建订单"
  }
}
```

JSON 的嵌套就是键名的层级：上面的键是 `order.count` 和 `order.created`。键名的每一段都不能包含 `.`。

也可以一种语言一个目录，目录里的文件名（和子目录名）作为键名的前缀：

```
locales/
  zh-TW/
    order.json         → order.*
    admin/user.json    → admin.user.*
```

两种布局可以在同一个目录里混用。

## 配置

```ts
import {Application} from 'lakutata'
import {BuildI18nOptions} from 'lakutata/com/i18n'

Application
    .alias({'@locales': '/path/to/locales'})
    .run(() => ({
        id: 'shop',
        name: 'Shop',
        components: {
            i18n: BuildI18nOptions({
                directory: '@locales',               //支持别名，也可以是数组
                defaultLocale: 'en',                 //默认语言，也是最后的回退语言（默认 en）
                fallback: {'zh-TW': 'zh-CN'},        //可选：繁体缺少的消息用简体的
                currency: 'CNY',                     //可选：{price, number, currency} 的默认货币
                timeZone: 'Asia/Shanghai'            //可选：日期和时间的时区（默认是进程的时区）
            })
        }
    }))
```

翻译也可以不放在目录里，直接在代码里传入：`messages` 选项按语言给出翻译映射，可以是对象字面量，也可以是 `import` 进来的 JSON。这样翻译和代码一起打包（`lakutata bundle`），运行时不读取任何文件：

```ts
import en from './locales/en.json' with {type: 'json'}
import zhCN from './locales/zh-CN.json' with {type: 'json'}

BuildI18nOptions({
    messages: {
        'en': en,
        'zh-CN': zhCN,
        'ja': {order: {created: '{customer} の注文を作成しました'}}
    }
})
```

| 选项 | 说明 |
|---|---|
| `directory` | 翻译文件所在的目录，可以是多个，支持别名 |
| `locales` | 支持的语言；不写则以加载到的语言为准（加上默认语言） |
| `defaultLocale` | 默认语言，默认 `en` |
| `fallback` | 某种语言缺少消息时，接着去哪些语言里找 |
| `messages` | 在代码里直接给出的消息（按语言），在目录之后加载，同名的键会覆盖；只用它时不需要 `directory` |
| `missing` | 缺少消息或参数时：`'throw'` 抛出异常；`'key'` 返回键名（参数原样保留为 `{name}`）并发出一次警告。默认抛出，`NODE_ENV=production` 时返回键名 |
| `currency` | 消息和参数都没有指定货币时使用的货币（ISO 4217） |
| `timeZone` | 日期和时间的时区（IANA） |
| `validationMessages` | 是否注册支持的语言的内置校验消息，默认 `true`（见“校验错误的翻译”） |

## 使用

```ts
import {Inject} from 'lakutata/decorator/di'
import {type I18n} from 'lakutata/com/i18n'

class OrderService extends Provider {
    @Inject('i18n')
    protected readonly i18n: I18n

    public summary(count: number, locale: string): string {
        return this.i18n.t('order.count', {count: count}, locale)
    }
}
```

| 方法 | 说明 |
|---|---|
| `t(key, params?, locale?)` | 某种语言下的消息，用参数格式化；不传语言时使用默认语言 |
| `has(key, locale?)` | 某种语言（或它回退到的语言）是否有这个键 |
| `format(message, params?, locale?)` | 格式化一条不在翻译文件里的 ICU 消息 |
| `translator(locale)` | 得到绑定某种语言的翻译器（`ITranslator`），之后不用每次都传语言 |
| `negotiate(requested)` | 从请求方希望的语言（优先的在前）中选出一种支持的语言，都不支持时用默认语言 |
| `addMessages(locale, messages)` | 运行时添加某种语言的消息，同名的键会覆盖 |
| `getLocales()`、`getDefaultLocale()`、`getKeys(locale)` | 支持的语言、默认语言、某种语言自己的键 |

### 按请求的语言回复

在 Entrypoint 上加上 `I18nMiddleware`，每个请求就会确定自己的语言；请求里的对象注入 `Translator`，直接得到这种语言的消息：

```ts
import {BuildEntrypoints, Controller} from 'lakutata/com/entrypoint'
import {CLIAction, GET} from 'lakutata/decorator/ctrl'
import {Inject} from 'lakutata/decorator/di'
import {BuildI18nOptions, I18nMiddleware, Translator} from 'lakutata/com/i18n'

class OrderController extends Controller {
    @Inject(Translator)
    protected readonly i18n: Translator

    @GET('/orders/count')
    @CLIAction('count-orders')
    public async count(): Promise<string> {
        return this.i18n.t('order.count', {count: await this.countOrders()})
    }
}

Application.run(() => ({
    components: {
        i18n: BuildI18nOptions({directory: '@locales'}),
        entrypoint: BuildEntrypoints({
            controllers: [OrderController],
            middlewares: [I18nMiddleware],
            http: ExpressHTTPEntrypoint({port: 3000})
        })
    }
}))
```

请求要的语言按以下顺序读取，再和支持的语言协商（见下文），都不支持时用默认语言：

| 入口 | 来源（优先的在前） |
|---|---|
| HTTP（Express、Fastify） | Query 参数 `?lang=`、Cookie `lang`、请求头 `Accept-Language` |
| Socket.IO | 连接时的 Query 参数 `lang`、Cookie `lang`、`Accept-Language` |
| 命令行 | 环境变量 `LC_ALL`、`LC_MESSAGES`、`LANG`，再是进程的语言 |
| Electron IPC | 主进程的环境变量和语言 |
| 定时任务 | 无（默认语言） |

- 同一个请求里的对象（Controller、`@Scoped` 的 Provider、访问控制规则）注入的是同一个 `Translator`；`translator.locale` 是这个请求的语言，`context.locale` 也是。
- 中间件使用名为 `i18n` 的组件。组件用了别的名字、要换 Query 参数名或 Cookie 名，或者要用别的方式决定语言（比如登录用户保存的语言），就继承 `I18nMiddleware`：

  ```ts
  class LanguageMiddleware extends I18nMiddleware {
      @Inject('lang')
      protected readonly i18n: I18n

      protected readonly queryParameter: string = 'locale'

      protected requested(context: BaseContext): string[] {
          return [...this.userLanguages(context), ...super.requested(context)]
      }
  }
  ```

- 没有配置 `I18nMiddleware` 时使用 `Translator` 会抛出 `I18nTranslatorException`。
- 翻译器（`Translator` 和 `translator(locale)` 得到的 `ITranslator`）有 `locale`、`t(key, params)`、`has(key)`、`format(message, params)`、`number(value, options)` 和 `date(value, options)`。
- 自己处理语言时，可以用 `ParseAcceptLanguage(header)` 解析 `Accept-Language`，用 `EnvironmentLocales()` 读取环境变量里的语言（`zh_CN.UTF-8` 会转换为 `zh-CN`），再交给 `negotiate()`。
- 不在请求里的地方（定时任务、单例组件），用组件的 `t(key, params, locale)` 或 `translator(locale)`。

## 校验错误的翻译

配置了 `I18nMiddleware` 时，请求参数（`@HTTPAction`、`@CLIAction`、`@ServiceAction` 的 DTO）校验失败的消息使用请求的语言。

框架内置了 20 种语言的校验消息，组件启动时为它支持的每种语言注册（只加载用到的语言）：

`en`、`zh-CN`、`zh-TW`、`ja`、`ko`、`fr`、`de`、`es`、`pt-BR`、`it`、`nl`、`pl`、`ru`、`uk`、`tr`、`vi`、`th`、`id`、`hi`、`ar`

支持的语言使用最接近的内置语言：`zh`、`zh-Hans`、`zh-SG` 使用 `zh-CN`，`zh-Hant`、`zh-HK`、`zh-MO` 使用 `zh-TW`，其他语言按语言部分匹配（`pt-PT` 使用 `pt-BR`，`fr-CA` 使用 `fr`）。没有内置消息的语言使用它回退到的语言的，最后是英文。

应用可以在翻译里覆盖或补充校验消息：写在 `validation` 下，键是校验的错误码，消息使用校验的模板语法（`{{#label}}`、`{{#limit}}`），不是 ICU：

```json
{
  "validation": {
    "any": {"required": "请填写 {{#label}}"},
    "string": {"min": "{{#label}} 至少 {{#limit}} 个字符"}
  }
}
```

- 某种语言的校验消息依次叠加：回退到的语言的内置消息和应用消息，再是它自己的内置消息和应用消息，后面的覆盖前面的。
- `validationMessages: false` 不注册内置消息，只使用应用的 `validation` 消息。
- 请求参数先按原来的方式校验；只有校验失败时，才按请求的语言再校验一次，取得该语言的消息。校验通过的请求不受任何影响。
- 少数消息里有校验引擎填入的英文内容，例如排序方向（`ascending`）、引用错误的原因、自定义断言的消息，这些部分在各语言里仍是英文。
- 不使用 i18n 组件时，也可以直接用 `lakutata` 的函数：`LoadValidationMessages(language)` 加载某种语言的内置消息，`RegisterValidationMessages(language, messages)` 注册，之后校验时用 `{errors: {language}}` 选项指定语言。

## 语言的协商与回退

**协商**（`negotiate`）：依次看请求方的每一种语言，先找完全相同的标签，再找只有语言部分的标签（`en-GB` → `en`），再找同一语言的其他地区（`pt-PT` → `pt-BR`，按支持的语言的顺序）；都找不到时使用默认语言。

**回退**：在某种语言里找不到消息时，依次查找：它在 `fallback` 里配置的语言、去掉最后一段的标签（`zh-Hant-TW` → `zh-Hant` → `zh`）、默认语言。消息总是按**请求的语言**格式化：回退到英文的消息，在德语请求里数字仍然是 `1.000`。

## 消息语法

| 语法 | 例子 |
|---|---|
| 参数 | `你好，{name}` |
| 数字 | `{n, number}`、`{n, number, integer}`、`{n, number, percent}` |
| 货币 | `{price, number, currency}`（货币来自参数 `currency` 或配置）、`{price, number, currency/EUR}` |
| 日期、时间 | `{at, date, short}`、`{at, time, long}`，样式为 `short`、`medium`、`long`、`full`；值可以是 `Date`、时间戳、日期字符串或有 `toDate()` 的对象 |
| 复数 | `{count, plural, =0 {还没有} one {# 个} other {# 个}}`：先匹配 `=数值`，再按该语言的复数规则；`#` 是格式化后的数字；支持 `offset:1` |
| 序数 | `{place, selectordinal, one {#st} two {#nd} few {#rd} other {#th}}` |
| 选择 | `{role, select, admin {管理员} other {用户}}` |
| 转义 | `''` 是一个撇号；`'{literal}'` 原样输出花括号（复数里的 `'#'` 原样输出 `#`） |

`plural`、`selectordinal` 和 `select` 必须有 `other`。消息在第一次使用时解析并缓存，语法错误会指出所在的语言、键和位置，例如 `zh-CN: order.count: the "other" option is required at 1`。

## 键名的类型

应用可以声明键名和它们的参数，之后写错键名或漏掉参数时编译就会报错：

```ts
declare module 'lakutata/com/i18n' {
    interface I18nMessages {
        'order.count': { count: number }
        'order.created': { customer: string }
    }
}
```

没有声明时，`t()` 接受任意键名和参数。

## 异常

| 异常 | 时机 |
|---|---|
| `I18nCatalogException` | 翻译文件或配置无效：JSON 有误、文件名不是语言标签、目录不存在、别名无法解析 |
| `I18nMessageSyntaxException` | 消息的语法错误 |
| `I18nMissingKeyException` | 找不到键（`missing: 'throw'`） |
| `I18nMissingParameterException` | 缺少参数（`missing: 'throw'`），或货币类消息没有可用的货币 |
| `I18nTranslatorException` | 没有配置 `I18nMiddleware` 时使用请求的 `Translator` |
